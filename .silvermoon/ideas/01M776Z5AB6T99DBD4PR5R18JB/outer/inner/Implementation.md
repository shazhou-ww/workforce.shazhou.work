# Implementation

本契约为准备阶段的可调整实施初版；本次只交付构想文档与离线原型，不实现生产功能。

## Steps

### I-S01: 建立身份与邀请授权边界

补齐可信邮箱验证、邀请领取、稳定用户身份和管理员检查；统一保护配置、结果、任务与定时入口，支持撤销和停用。

### I-S02: 隔离个人配置与采集结果

将全局配置、状态、发布锁与快照演进为用户归属明确的资源，保留配置版本、失败重试和完整发布语义；准备保留现有公开看板的迁移方案及平台资源控制。

### I-S03: 实现个人与管理员操作界面

在既有视觉语言下实现首次配置、个人看板、邀请管理及访问受限状态，并增加直接覆盖新行为的测试。

## Acceptance criteria

### I-AC01: 授权与归属不可绕过

通过 API 与任务入口测试证明：未获邀或被停用用户不能读取或修改个人资源，用户不能跨归属访问；邮箱未验证不能领取邀请，已有会话不绕过停用。

### I-AC02: 统计行为与发布可靠性保持

用固定提交样本和迁移测试证明原有统计口径、公开看板、配置版本固定与失败保留旧快照行为不变；并验证配额与并发限制。

### I-AC03: 新增操作可完成且可理解

用界面测试与桌面、移动端人工检查覆盖首次配置、保存、刷新、邀请、撤销、停用和失败提示，运行仓库规定的 pnpm
check。
