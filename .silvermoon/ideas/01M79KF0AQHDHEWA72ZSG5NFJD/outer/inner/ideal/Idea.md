# 优先展示近月统计，后台补齐年度足迹

## 问题

首次采集为年度热力图读取一年历史后才展示近月结果，导致用户长时间等待。

## 结果

先完成所选范围最近 30 个北京时间日的统计并展示，再后台分批补齐更早的年度足迹；后续刷新复用有效历史，不反复拉满一年。

## 边界

- 先解决私有仓库首次采集；保留公开采集、分享及用户隔离行为，不扩大 GitHub 授权。
- 未采集日期明确标为待补齐，不能显示为零提交；后台失败不得撤掉已完成的近月结果。
- 补采、缓存读取与结果展示遵守当前授权；替换选择、撤权和断开不能让旧任务恢复数据。

## 验收标准

- 年度补采结束前，所选范围的完整近月统计已可见，不把部分仓库结果冒充完整统计。
- 热力图区分已知零值与未知日期，补采进度、失败及恢复状态清晰可见。
- 同一数据集验证首次近月结果早于全年完成，恢复与后续刷新不重复拉取有效历史，且授权和公开隔离回归通过。
