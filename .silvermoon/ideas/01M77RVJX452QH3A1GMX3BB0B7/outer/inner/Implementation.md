# Implementation

采用最小实时资格查询与有界仓库批处理优化热缓存采集，不改变统计口径、变化历史检查点、最终发布授权或既有资源配额。实现、最新主线集成与受控对照已完成，主代理重新执行
`pnpm check`
通过，详见[采集性能实施证据](performance-verification.md)及[原始测量](benchmark-results.json)；受控延迟模型结果不等同于生产收益，发布及真实样本验证按部署门限推进。

## Steps

### I-S01: 建立可比测量与精简实时检查

以含旧采集退役与指定个人公开投影的版本建立固定负载对照，分别记录数据库调用、SQL、回调、活跃时间与墙钟时间。每个个人采集回调前后以新的
`first-primary`
会话执行单次必要字段联表查询，保留实时停用、取消、配置与发布锁归属检查，以及最终原子发布条件。

### I-S02: 建立缓存命中的批量快速路径

通过版本化 `reuse-plan:v1`
检查点固定成员，按最多 10 仓库串行批量规划及聚合，事务内同时提交统计与完成标记；复用本轮固定配置、截止时间与作者邮箱 HMAC，但仍重算移动窗口。变化与全量历史保留逐仓库固定 SHA、分页游标和重试检查点，候选快照校验暂保持原样，不引入大型 Workflow 载荷。

### I-S03: 验证正确性与性能门槛

以相同提交集、配置、截止时间和环境执行三组 70 仓库混合负载成对对照，另列全复用及首次初始化参考；明确披露注入延迟与生产未知项。比较完整统计语义，验证批次回滚、取消、停用、归属丢失、旧检查点恢复、发布 fencing 和配额保持，并执行
`pnpm check`；集成最新主线后重新验证，不覆盖公开资料功能及其迁移。

## Acceptance criteria

### I-AC01: 性能收益可复现

约 70 仓库、至少 95% 缓存命中的无外部等待负载，至少三组成对运行的规划与聚合合计处理时间中位数降低至少 70%；提供数据库往返、步骤及 GitHub 请求计数。历史生产数据用于背景，不替代同环境对照。

### I-AC02: 统计和授权保持

固定数据、配置与截止时间下语义结果一致；覆盖 30 天、365 天、滚动窗口、作者匹配、排除与可达历史，以及已有会话停用、跨用户拒绝和发布原子资格检查。

### I-AC03: 重试和资源行为保持

证明批次中断重放不重复或遗漏结果，旧快照保留、取消和新旧发布顺序正确；首次与变化仓库路径不退化，现有配额不变，`pnpm check`
通过。
