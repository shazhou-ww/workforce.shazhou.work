# Implementation

## Steps

### I-S01: 拆分近月就绪与年度补采状态

明确近月完整结果、年度覆盖范围及独立失败状态，保持固定截止时间和统计口径；界面将未知日期与零提交区分。

### I-S02: 实现可恢复的分批补采与历史复用

先发布全部选中仓库的近月结果，再补更早日期；用用户及授权绑定的进度和缓存支持恢复、增量刷新，处理配置变化与撤权竞争。

### I-S03: 验证正确性与首屏提速

使用可重复的大历史数据集对比首个近月结果、全年完成时长与请求量，测试补采失败恢复及隔离，并记录测量结果。

## Acceptance criteria

### I-AC01: 近月结果不等待全年

测试拦住较早历史页时，最近 30 天所有选中仓库的完整统计已发布；最终结果与相同截止时间的全量基线一致。

### I-AC02: 补采状态及复用可靠

测试未知日期不被填零，补采失败保留近月结果且可恢复；请求记录证明后续刷新或恢复不重复获取仍有效的历史区间。

### I-AC03: 性能与隔离有证据

记录同一数据集的近月首次可见时间、全年完成时间和请求量；授权撤销、旧任务竞争、跨用户及公开分享测试与 pnpm
check 通过。
