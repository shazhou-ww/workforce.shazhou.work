# Deployment

## Steps

### D-S01: 准备外部授权与受控验证

落实选定授权方案所需的应用配置和企业审批，使用明确获准的测试仓库与账号；不把真实凭据或私有仓库内容写入跟进文档。

首版不新增 GitHub
App，复用现有服务身份与加密密钥。由验收用户在「个人配置 → 私有仓库」提供自己的 fine-grained
PAT，选择指定仓库及 Contents/Metadata 只读权限；组织审批由资源所有者处理。未取得真实验收令牌时，不宣称已完成首次私有采集。

### D-S02: 按生产流程发布

取得明确发布授权后，同步最新主线并通过检查，使用新的 Release 标签触发现有 Cloudflare 工作流；准备功能关闭和数据处置方案。

沿用现有受权 D1 连接在创建 Release 标签前应用迁移，现有 Release
Action 执行检查并部署 Worker 与静态资源，不扩大仅部署用途的 Actions 凭据权限。新增迁移
`0006_private_repositories.sql`
仅创建独立表，兼容旧 Worker。发布前核对数据库已应用迁移与部署版本；失败不复用或移动标签。

### D-S03: 验证线上访问及撤权

核对本人统计、跨用户和匿名访问、公开主页及权限撤销后的实际行为。

发布后先检查健康接口、登录入口、私有 API 的匿名拒绝及公开功能，再由获准用户执行真实 PAT 连接、刷新和撤权。断开入口删除当前私有授权及快照并使旧任务失效；需要全局关闭时通过后续 Release 恢复不含私有入口的 Worker，保留数据库等待明确数据处置授权，不直接删除公共或私有数据表。

## Acceptance criteria

### D-AC01: 线上授权与统计可用

以获准账号完成选仓和采集，确认私人统计可见；保留脱敏的验证结果。

### D-AC02: 线上私有边界有效

使用另一账号及匿名访问验证公开输出无私有信息或统计；撤销授权后确认停止采集且旧数据遵守约定规则。

### D-AC03: 发布与现有功能正常

确认部署工作流成功、生产 API 与 UI 正常、公开仓库和分享功能可用，并记录已验证的关闭及数据处置方式。
