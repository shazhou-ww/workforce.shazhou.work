# 个人配置与统计口径

本文是 [构想](Idea.md) 的理想世界 supporting
document，解释产品配置边界，不是已实现的 API 或数据库契约。

## 一个用户，一套方法

每个获邀用户拥有一份个人配置、一套当前统计结果和自己的任务记录。第一版不增加多方案选择器，也不做跨用户聚合、比较或排名。底层缓存是否复用不影响这个产品边界，也不是本次的前置工程。

## 个人配置 review

| 现有字段              | 用户看到的名称                 | 默认与语义                                                                           |
| --------------------- | ------------------------------ | ------------------------------------------------------------------------------------ |
| `authorLogins`        | 用于识别本人提交的 GitHub 账号 | 能可靠取得本人 GitHub 账号时预填；否则由用户填写。允许多个，不用显示名识别作者。     |
| `authorEmails`        | 用于识别本人提交的邮箱         | 可选，可填写多个旧邮箱或 GitHub noreply 邮箱；只匹配主作者，不识别提交者或共同作者。 |
| `accounts`            | 扫描的个人账号或组织           | 与作者身份分开；扫描组织不等于计入组织中所有人的贡献。                               |
| `repositoryMode`      | 仓库范围                       | “账号名下公开仓库”与“仅指定公开仓库”两种模式。                                       |
| `includeRepositories` | 指定纳入的仓库                 | `owner/name`，也可纳入不在上述账号名下的公开仓库。                                   |
| `excludeRepositories` | 排除的仓库                     | 排除优先于自动发现和明确纳入；处理仓库重命名时保留现有按 ID 解析的行为。             |
| `enabled`             | 自动更新                       | 首次有效配置后可启用，用户可以暂停；不能覆盖平台全局关闭或管理员停用。               |

至少有一个作者账号或邮箱。作者账号与邮箱之间为“或”关系，不是必须同时匹配；邮箱的“过滤”指纳入匹配，不是排除这些邮箱。仓库范围为：

```text
（按模式启用的账号名下公开仓库 ∪ 指定纳入仓库）− 排除仓库
```

“账号名下公开仓库”模式要求非空扫描账号，“仅指定”模式要求非空纳入列表。界面应说明各列表一行一项，规范化大小写、去重，并明确拒绝非法值。旧配置的数组最多 100 项只是输入校验，不代表平台允许每人采集 100 个仓库。

## 两种邮箱不能混用

- 邀请邮箱用于证明平台使用资格，必须经过可信验证。
- 统计邮箱用于匹配公开历史提交，不用于领取邀请、登录或提升权限；旧邮箱可能已不可收信，第一版不要求它仍能通过邮件验证。
- 填写统计邮箱不证明提交归属。工具用于个人自查，不提供身份认证或“代码确属本人”的证明。
- 配置邮箱不得出现在公开快照、日志、原型真实样例或代码仓库；继续保留受保护配置和提交缓存中的 HMAC 指纹机制。

## 不提取为个人参数

沿用现有默认分支、主作者匹配、北京时间、30 个日历日、365 天热力图、滚动 24 小时变化、新增加删除行数，以及 fork、归档仓库、merge 与跨仓库 SHA 的统计方式。仓库列表继续支持搜索、零变化项目开关和日期选择。

统计是代码活动，不是生产力或质量判断。GitHub 采集凭据、邮箱指纹密钥、全局调度开关、任务并发和配额不交给用户。私有仓库、自由 Cron、通用规则表达式与公开分享不属于第一版。

## 修改与失败反馈

个人配置从看板顶部按钮打开 modal dialog
panel，不新增侧边栏或独立配置路由。关闭、取消或 Escape 放弃未保存草稿；保存成功后返回原看板并提示，校验失败保留弹框与错误字段。

保存成功只表示配置生效，不意味着采集完成。新任务固定配置版本和截止时间；运行中编辑配置不改变在途任务，下次任务使用新版本。旧快照在新版本成功前保留，并显示“配置已更新，当前结果来自上一配置”。

首次尚无快照时显示真实空状态，不生成零统计。暂停只停止后续自动更新，手动刷新仍受授权与配额约束。采集失败显示可理解原因并保留上次完整结果，不能静默跳过仓库后声称完整。

## 现有服务兼容

保留目前主页公开看板；管理员也拥有自己的个人空间，但不能把现有公开资源直接变成所有用户共用的“个人空间”。新增用户的配置、任务与结果默认仅本人可见，不发布新的公开个人链接。具体迁移映射在实施阶段明确，不能丢失已有快照或部署功能。
