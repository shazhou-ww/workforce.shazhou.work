# 实现验收证据

本文支持 [Implementation](Implementation.md)，不替代构想或现实世界验收。

## I-AC01：授权与归属

Worker 的个人集成测试覆盖可信邮箱领取、稳定身份、不按邮箱合并账号、管理员引导、邀请撤销与停用恢复、跨用户资源拒绝、CSRF、单次且绑定会话的 OAuth 连接意图，以及加密凭据的用户绑定。旧会话需要重新登录；未验证的提供商邮箱不能领取邀请。

每次个人请求和任务检查点执行实时资格检查，发布更新同时校验资格与任务归属。已停止用户不发布新快照，取消状态不会被迟到的失败回调覆盖。工作流检查失败显式返回 503，不伪装成正常进行中。

本地实际 HTTP 检查：资格接口对匿名请求返回 200 的未登录状态；个人配置、统计与管理员邀请接口均返回 401，响应均为
`private, no-store`。

## I-AC02：统计与迁移

定向测试覆盖填充了历史配置、任务、提交缓存及公开状态的数据库迁移，校验外键与历史数据保留。个人配置、状态锁、同步水位及完整快照隔离；公开
`activity:v1` 不受个人发布影响。旧公开范围不受新增个人 50 仓库上限影响。

仓库展开后计数、按 ID 排除、每次拉取历史预算、冷却、并发预留和有界定时调度均有回归用例。状态表选择使用明确的内部表名与参数化 ID，不重写任意 SQL 文本。

前端测试覆盖原生模态面板、焦点和取消、组织错误保留、逐项仓库列表、OAuth 草稿恢复警告、保存提示、邀请操作确认、访问受限状态和个人任务展示。登录文案区分邀请资格、个人空间及公开看板；个人 API 错误提供中文提示。

## 组织授权回跳补充修正

首次发布后的真实内置浏览器走查确认：账户已获
`read:org`，但组织仍对该 OAuth 应用设置独立限制，GitHub 合法返回空列表。用户明确选择放行后，原接口即返回 4 个组织，生产弹框出现对应勾选项；没有替用户保存统计范围。

补充修正已明确解释组织放行、提供当前 GitHub 应用的访问设置入口，并在授权回跳后定位到组织选择区域。从 GitHub 设置返回窗口时重新读取组织，保留已有勾选；未添加的输入不会先创建 OAuth 意图。组织发现继续使用受 GitHub 组织策略约束的原接口，不绕过组织限制。

普通登录仅在旧凭据通过服务端身份及 `read:org`
实时检查后保留已有组织连接，否则使用新凭据并要求重新授权。新增回归覆盖有效、失效、错误身份及读取失败等情况。

修正后的完整 `pnpm check` 通过：contracts 7 项、Worker 212 项、web
124 项，以及格式、lint、类型检查、覆盖率和全部构建；Turborepo 共 12 项任务成功。
