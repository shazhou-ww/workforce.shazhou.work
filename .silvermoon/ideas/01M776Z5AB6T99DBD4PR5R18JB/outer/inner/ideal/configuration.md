# 个人配置与统计口径

本文是 [构想](Idea.md) 的理想世界 supporting
document，解释产品配置边界，不是已实现的 API 或数据库契约。

## 一个用户，一套方法

每个获邀用户拥有一份个人配置、一套当前统计结果和自己的任务记录。第一版不增加多方案选择器，也不做跨用户聚合、比较或排名。底层缓存是否复用不影响这个产品边界，也不是本次的前置工程。

## 个人配置 review

| 现有字段              | 用户看到的名称              | 默认与语义                                                                           |
| --------------------- | --------------------------- | ------------------------------------------------------------------------------------ |
| `authorLogins`        | GitHub 主账号与历史作者账号 | 主账号通过 OAuth 连接取得，只读展示；可补充历史账号作为匹配条件，不冒充已验证身份。  |
| `authorEmails`        | 用于识别本人提交的邮箱      | 可选，可填写多个旧邮箱或 GitHub noreply 邮箱；只匹配主作者，不识别提交者或共同作者。 |
| `accounts`            | 扫描的个人账号或组织        | 勾选本人公开仓库及读取到的已加入组织；可手动补充其他公开账号或组织。与作者身份分开。 |
| `repositoryMode`      | 仓库范围                    | “账号名下公开仓库”与“仅指定公开仓库”两种模式。                                       |
| `includeRepositories` | 指定纳入的仓库              | 搜索公开仓库或填写 `owner/name`，逐项添加、移除，也可纳入其他账号名下的公开仓库。    |
| `excludeRepositories` | 排除的仓库                  | 独立的逐项列表；排除优先，处理仓库重命名时保留现有按 ID 解析的行为。                 |
| `enabled`             | 自动更新                    | 首次有效配置后可启用，用户可以暂停；不能覆盖平台全局关闭或管理员停用。               |

至少有一个作者账号或邮箱。作者账号与邮箱之间为“或”关系，不是必须同时匹配；邮箱的“过滤”指纳入匹配，不是排除这些邮箱。仓库范围为：

```text
（按模式启用的账号名下公开仓库 ∪ 指定纳入仓库）− 排除仓库
```

“账号名下公开仓库”模式要求非空扫描账号，“仅指定”模式要求非空纳入列表。账号、仓库列表规范化大小写并去重；仓库采用逐项添加，不以多行文本框编辑。历史账号和匹配邮箱仍可一行一项。旧配置的数组最多 100 项只是输入校验，不代表平台允许每人采集 100 个仓库。

## GitHub 连接与组织选择

先取得平台邀请资格，再配置个人 GitHub 连接。GitHub 登录用户复用已确认的提供商身份，权限不足时补充授权；其他登录方式用户使用“连接 GitHub”显式绑定。主账号显示头像、login 与连接状态，不提供任意编辑框；稳定 ID 来自服务端 OAuth 结果，不相信浏览器填写的身份。

读取“我加入的组织”，不称为“我拥有的组织”，也不要求用户是组织 owner。本人公开仓库单独勾选；组织列表显示名称与勾选项，支持刷新，保留手动添加公开账号或组织以覆盖非成员贡献。刷新不自动勾选新组织，读取失败或权限不足不能伪装成空列表，也不能清除已保存的选择。

组织读取按需申请 `read:org`，不为公开仓库统计申请宽泛的 `repo`
权限。组织策略、权限缺失、读取失败需提供具体说明、补充授权或重试入口；成员关系列表不证明有权访问私有代码，也不改变只采集公开仓库的边界。

主账号连接和组织列表读取属于外部身份／元数据状态，不因取消配置草稿而撤销已完成的 OAuth 授权；取消只恢复仓库勾选、逐项列表及其他未保存配置。若连接失效，应明确提示重新连接，不静默换成其他用户身份。

## 纳入与排除的逐项列表

两份列表各有搜索／输入框、“添加”按钮及每项“移除”按钮。优先从读取到的公开仓库建议中选取，也允许手动输入其他
`owner/name`。按 Enter 添加当前条目，不误触保存整个配置。

重复项明确提示；格式非法、仓库不存在、非公开与暂时无法校验应区分反馈。两个列表均出现同一仓库时保留显式冲突提示，说明排除优先，不静默改变用户输入。保存时若输入框仍有尚未添加的内容，应提示先添加或清空，避免丢失草稿。

正式产品在保存或发现阶段由服务端核验仓库身份、公开性和展开后的配额，未确认仓库不能被当作已核验结果。离线原型只做语法校验，示例搜索建议明确标注为虚构；手动输入的未知仓库显示“待上线核验公开性”，不假装已经调用 GitHub。

## 两种邮箱不能混用

- 邀请邮箱用于证明平台使用资格，必须经过可信验证。
- 统计邮箱用于匹配公开历史提交，不用于领取邀请、登录或提升权限；旧邮箱可能已不可收信，第一版不要求它仍能通过邮件验证。
- 填写统计邮箱不证明提交归属。工具用于个人自查，不提供身份认证或“代码确属本人”的证明。
- 配置邮箱不得出现在公开快照、日志、原型真实样例或代码仓库；继续保留受保护配置和提交缓存中的 HMAC 指纹机制。

## 不提取为个人参数

沿用现有默认分支、主作者匹配、北京时间、30 个日历日、365 天热力图、滚动 24 小时变化、新增加删除行数，以及 fork、归档仓库、merge 与跨仓库 SHA 的统计方式。仓库列表继续支持搜索、零变化项目开关和日期选择。

统计是代码活动，不是生产力或质量判断。GitHub 采集凭据、邮箱指纹密钥、全局调度开关、任务并发和配额不交给用户。私有仓库、自由 Cron、通用规则表达式与公开分享不属于第一版。

## 修改与失败反馈

个人配置从看板顶部按钮打开 modal dialog
panel，不新增侧边栏或独立配置路由。关闭、取消或 Escape 放弃未保存草稿；保存成功后返回原看板并提示，校验失败保留弹框与错误字段。

保存成功只表示配置生效，不意味着采集完成。新任务固定配置版本和截止时间；运行中编辑配置不改变在途任务，下次任务使用新版本。旧快照在新版本成功前保留，并显示“配置已更新，当前结果来自上一配置”。

首次尚无快照时显示真实空状态，不生成零统计。暂停只停止后续自动更新，手动刷新仍受授权与配额约束。采集失败显示可理解原因并保留上次完整结果，不能静默跳过仓库后声称完整。

## 现有服务兼容

保留目前主页公开看板；管理员也拥有自己的个人空间，但不能把现有公开资源直接变成所有用户共用的“个人空间”。新增用户的配置、任务与结果默认仅本人可见，不发布新的公开个人链接。具体迁移映射在实施阶段明确，不能丢失已有快照或部署功能。
