# 新增 UX 与离线评审

直接用浏览器打开
[prototype.html](prototype.html)。单文件包含全部样式、脚本和示例数据，不加载字体、图片、CDN、API 或其他网络资源，不需要启动开发服务。

所有身份、邮箱、仓库和统计数字均为虚构示例；交互仅修改当前页面内存，刷新文件即可重置。没有真实登录、授权、邮件发送、采集或数据持久化。顶部“原型场景”是评审工具，不是生产环境允许用户切换身份的控件。

## 视觉方向

继承现有 Workforce 的主色 `#2255d7`，而不是重新品牌化。基础色为纸白
`#ffffff`、淡蓝灰 `#f4f7ff`、墨蓝 `#18243b`、次要文字 `#53627a`，提醒使用深琥珀
`#805500`。字体使用离线可用的 Segoe
UI、微软雅黑和系统无衬线，数字采用等宽数字排版。

桌面为安静的左侧个人导航、左对齐主内容与右侧统计范围摘要；小屏折叠为顶部导航并纵向排列。配置按“识别谁的提交”和“去哪里找提交”分区，邀请页以真正的用户表格为主，不用营销卡片或排行。唯一醒目的结构是配置页旁的“统计范围”，帮助用户理解作者与仓库是不同维度。

设计校准：不新增通用 SaaS 渐变首屏、指标卡阵列或新字体下载；保持现有蓝白色系，把视觉重点用于说明个人归属与授权状态。

## 建议走查顺序

1. **平台主页**：保留现有公开看板的入口，并区分登录后的个人空间。
2. **首次配置**：填写 GitHub 作者账号、历史邮箱，选择自动发现或指定仓库；预览匹配语义，保存后进入等待首次采集状态。
3. **我的统计**：查看虚构个人结果，模拟手动刷新及冷却；暂停自动更新、保留旧结果与配置变更提示应可理解。
4. **用户管理**：添加邀请、重复邮箱提示、撤销待领取邀请、停用已授权用户、恢复资格。每个变更均只影响示例列表。
5. **未获邀**：已登录也不能进入个人空间；不提供“注册即可使用”的按钮。
6. **邮箱待验证**：说明为何不能领取邀请，演示“开始验证”反馈，但不冒充邮件已发送。
7. **已停用**：说明已有会话不能继续使用；管理员恢复前没有“立即刷新”等绕过入口。

## 状态与反馈

| 操作或状态         | 所需反馈                                         |
| ------------------ | ------------------------------------------------ |
| 首次未配置         | 引导保存个人范围，不展示假零值                   |
| 配置保存           | 说明已保存、需新采集；已有结果仍属于旧版本       |
| 采集进行中         | 显示进度，禁用重复启动，不暗示已经完成           |
| 刷新冷却           | 解释最短间隔，原型提供重置演示入口               |
| 采集失败或额度不足 | 保留旧结果，显示原因和下一步，不声称部分结果完整 |
| 邀请添加           | 显示待领取，不声称邮件已发送                     |
| 撤销与停用         | 二次确认，说明邀请或后续服务受到的具体影响       |

原型提供“首次使用 / 已有结果 / 采集失败 / 配额不足”子场景，用于观察状态，不代表新增业务功能。示例结果中的图形只说明页面衔接，不取代现有生产图表；实施时继续复用当前图表及其无障碍行为。

## 可访问性与离线约束

表单有可见标签、语义化输入、键盘焦点和错误提示；操作结果使用状态区播报；危险操作使用原生对话框，取消后返回触发点，确认后返回邀请输入框。小屏页面整体不横向溢出，用户表格可在独立区域横向滚动。无自动动画、不使用真实个人数据、不写入浏览器存储。
