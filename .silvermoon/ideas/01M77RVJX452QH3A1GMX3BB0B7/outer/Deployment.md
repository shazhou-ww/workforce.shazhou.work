# Deployment

准备阶段的轻量现实世界初版。本次创建构想不授权生产发布，也不宣称优化已实现。

## Steps

### D-S01: 确认上线基线与并行迁移状态

核对旧采集退役和公开投影的最新主线、已部署功能及运行中任务；确认新的同环境性能基线、恢复策略和必要的数据迁移安排。

### D-S02: 按授权流程发布优化

获得明确发布授权且实现验收后，集成最新主线并运行检查，使用未占用 Release 标签触发现有 GitHub
Actions；不从本地直发 Worker。

### D-S03: 对照生产采集与发布结果

观察真实复用率、无等待时阶段耗时、请求与重试指标；检查个人结果、公开投影和权限边界，记录限流或平台波动，避免额外触发大量采集做压测。

## Acceptance criteria

### D-AC01: 部署与兼容性可核验

Actions 成功，生产 API 与 UI 正常；在途任务、现有个人配置、公开结果和同步状态没有被旧实现覆盖或清空。

### D-AC02: 生产收益有证据

在仓库范围和复用率可比、无 GitHub 等待的真实样本中报告阶段耗时及资源计数，趋势与实施阶段对照结论一致；不同环境的单次快慢不得当作达到 70% 门槛的唯一证据。

### D-AC03: 故障与隔离未退化

结合线上只读检查和实施回归，证明失败保留完整结果、发布有序、资格校验与个人隔离保持；日志不包含凭据、邮箱或私有配置。
