# Deployment

## Steps

### D-S01: 准备可比较的线上验证

选择明确获准且有较长历史的测试范围，明确观测近月就绪、年度补采和恢复的方式；不记录真实令牌或私有仓库内容。

分别覆盖公开与私有采集；公开范围可用于首个线上性能验证，真实私有范围必须获得用户授权。发布前基线为 Release-261113-4、数据库迁移 0001–0006；尚无已配置私有授权，不据此宣称真实私有性能已经验证。

### D-S02: 经现有流程发布兼容候选

取得明确发布授权后同步主线、通过检查，按需应用兼容迁移并以新的 Release 标签触发现有 Action，保留旧结果与停用恢复方案。

沿用现有受权 D1 连接在打标签前应用兼容迁移，不扩大仅 Worker 部署用途的 Actions 凭据权限。只通过 Release
Action 部署 Worker 和静态资源；旧全年任务、已有完整结果和公开主页必须兼容。

### D-S03: 验证渐进结果与权限边界

实测首次近月结果、后台补齐、后续刷新及失败恢复；核对授权变化和公开功能未回退。

记录公开和私有两条路径的验证状态；未取得真实私有凭据时只报告其本地证据及待验收项。未知年度日期不可作为零值公开。停用改造须使用后续 Release 恢复兼容版本，保留有效近月结果，不直接清空用户数据。

## Acceptance criteria

### D-AC01: 线上近月结果提前可用

记录同一首次任务的近月就绪与年度完成时间，证明年度补采期间近月结果已可用，热力图未知区间有明确提示。

### D-AC02: 线上补采与恢复有效

通过获准场景验证后续补齐、增量刷新及任务中断恢复，记录请求或进度证据，确认已完成近月结果不因补采失败消失。

### D-AC03: 发布与访问边界正常

确认 Action、生产 API 和 UI 正常；验证撤权、断开和公开访问不会泄露或恢复私有数据，记录可执行的停用恢复方案。
