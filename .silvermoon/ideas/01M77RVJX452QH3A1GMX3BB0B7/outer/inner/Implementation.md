# Implementation

准备阶段的轻量实施初版，本次仅记录构想与调研，不开始源代码优化。

## Steps

### I-S01: 建立可比测量与精简实时检查

核对最新迁移后的采集链路，建立固定负载基线并区分数据库执行、往返、步骤与 GitHub 等待；将后台资格检查收敛到必要字段，保留实时停用及任务归属校验。

### I-S02: 建立缓存命中的批量快速路径

按实测收益合并未变化仓库的规划与聚合，复用本轮不变量和不可变快照候选；变化历史保留独立可恢复游标，批量规模受运行时预算约束。

### I-S03: 验证正确性与性能门槛

在同一固定提交集、配置、截止时间和运行环境下做优化前后对照，补充失效、取消、重放、并发发布与时间边界回归，执行仓库规定检查。

## Acceptance criteria

### I-AC01: 性能收益可复现

约 70 仓库、至少 95% 缓存命中的无外部等待负载，至少三组成对运行的规划与聚合合计处理时间中位数降低至少 70%；提供数据库往返、步骤及 GitHub 请求计数。历史生产数据用于背景，不替代同环境对照。

### I-AC02: 统计和授权保持

固定数据、配置与截止时间下语义结果一致；覆盖 30 天、365 天、滚动窗口、作者匹配、排除与可达历史，以及已有会话停用、跨用户拒绝和发布原子资格检查。

### I-AC03: 重试和资源行为保持

证明批次中断重放不重复或遗漏结果，旧快照保留、取消和新旧发布顺序正确；首次与变化仓库路径不退化，现有配额不变，`pnpm check`
通过。
