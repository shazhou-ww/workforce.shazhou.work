# 优化缓存命中场景的采集性能

## 问题

个人采集在绝大多数仓库复用缓存、没有 GitHub 限流时仍需数分钟，重复权限查询、逐仓库检查点和聚合往返抵消了增量同步的收益。

## 结果

让缓存命中真正走低开销路径，减少数据库往返、串行步骤与重复计算，并以可复现的阶段指标证明提速，而非仅改善进度显示。

## 边界

- 不改变作者匹配、时间窗口、可达历史或统计结果，不削弱实时停用、用户隔离及完整发布保障。
- 优先优化增量采集；首次初始化、组织限流和旧采集退役分别衡量，不以盲目并发或扩容代替根因优化。
- 不绕过 GitHub 组织策略，不扩大权限；与并行迁移保持接口兼容。

## 验收标准

- 在固定约 70 仓库、至少 95% 缓存命中且无外部限流的对照负载下，规划与聚合合计处理耗时较同环境基线降低至少 70%。
- 数据库往返、Workflow 步骤、GitHub 请求及等待分别可核验，不以减少仓库、缩短历史或遗漏结果达到性能目标。
- 固定数据的优化前后统计一致，取消、停用、失败重试和并发发布回归通过。
