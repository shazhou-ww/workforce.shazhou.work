# Implementation

## Steps

### I-S01: 确定最小授权与撤权规则

评估 GitHub App 指定仓库只读授权，避免直接扩大登录 OAuth 的 repo 权限；明确企业审批、凭据生命周期和已有数据保留/删除规则。

### I-S02: 打通私有配置与隔离采集

支持明确选择私有仓库，调整发现、校验、历史采集及快照；审视当前按仓库共享的缓存，确保用户隔离及当前授权检查。

### I-S03: 隔离公开输出并补充验证

区分私人统计与公开投影，公开输出排除私有仓库信息及其聚合值；覆盖权限撤销、缓存复用和公开功能回归。

## Acceptance criteria

### I-AC01: 授权选择与采集可验证

通过集成测试证明仅已授权且主动选择的私有仓库可进入个人统计，拒绝或缺少权限时提供明确错误。

### I-AC02: 数据与缓存边界可验证

通过跨用户、匿名访问及撤权测试证明私有数据不会泄露，缓存不能替代当前授权；记录保留/删除规则及验证方式。

### I-AC03: 公开功能保持兼容

通过公开仓库及公开分享回归测试，并运行 pnpm check，证明公开投影不包含私有元数据或私有统计。
